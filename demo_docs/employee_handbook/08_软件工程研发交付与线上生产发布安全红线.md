# 华远科技集团软件工程研发交付与线上生产发布安全红线

**文档编号**：HY-DEV-2024-008  
**生效日期**：2024年01月01日  
**归口部门**：技术委员会、基础架构部、信息安全部  
**适用范围**：华远科技集团全体研发工程师、SRE运维工程师、QA测试工程师、DBA及产品技术负责人  

---

## 第一章 研发交付生命周期与质量门禁

### 第一条 目的与核心价值观
为确保华远科技集团核心系统与高并发分布式服务的高可用性、稳定性与数据安全性，规范代码工程化生命周期，筑牢线上生产安全防线，特制定本规范与安全红线。研发团队必须恪守“敬畏生产、变更受控、防御在先、快速止损”的工程价值观。

### 第二条 需求至发布的标准流程与质量门禁
所有核心业务系统及中后台微服务交付必须严格遵循以下六道工序与门禁卡点：
1. **技术方案与 RFC 架构评审**：
   - 凡涉及核心数据模型变更、跨域架构调整或单接口预估 QPS 超过 5000 的场景，必须撰写 RFC（Request for Comments）技术方案设计书，并召集技术委员会资深架构师完成评审。
2. **代码规范与双人审查（Code Review）**：
   - 代码分支严禁单人私自 Merge 入主干。PR/MR 必须由至少一名同项目组 P6/L6 以上资深研发人员进行严谨的双人 Code Review，并在 GitLab/GitHub 系统中通过 Approved 授权。
3. **单元测试与门禁流水线覆盖率**：
   - 核心系统业务逻辑代码单元测试行覆盖率（Line Coverage）基线不得低于 **80%**，分支覆盖率（Branch Coverage）不得低于 **70%**。流水线执行测试未通过或静态代码扫描（SonarQube）含阻断（Blocker）级缺陷的代码不得合入 Release 分支。
4. **性能压测与全链路演练**：
   - 重大版本发布前必须在预发环境（Staging）完成容量性能压测，确保在预估峰值流量 1.5 倍负载下，P99 延迟不超过 200 毫秒，错误率（Error Rate）低于 0.01%。

## 第二章 生产发布窗口与变更分级管控

### 第三条 发布变更分级
根据变更影响面与业务风险，将生产环境发布分为四级：
- **P0 级变更**：跨核心数据中心网络调整、核心数据库底层分库分表迁移、全站核心网关升级。
- **P1 级变更**：交易链路、支付清算、身份认证等核心主链路微服务发布与数据表结构变更。
- **P2 级变更**：非核心业务微服务、内部运营管理后台系统、常规功能迭代与非关键逻辑升级。
- **P3 级变更**：静态文案修正、埋点调整、无状态辅助任务配置更新。

### 第四条 允许发布时间窗口与封网（Freeze）规范
1. **标准允许发布窗口**：
   - **每周二、周三、周四** 的 **上午 10:00 - 11:30** 与 **下午 14:00 - 16:30**。
   - 严禁在每日午休（12:00 - 13:30）及晚间下班峰值期进行常规发布。
2. **常规封网期（Weekend Freeze）**：
   - **每周五 15:00 之后** 至 **下周一上午 09:30 之前**，全面禁止任何常规业务迭代发布上线，避免因周末值班人手不足导致故障扩散。
3. **重大节日与促销封网（Major Event Freeze）**：
   - 在国家法定长假（国庆、春节）前 3 个工作日，以及集团重大业务促销活动（如 618 大促、双 11、跨年狂欢）前 5 个工作日，全集团进入一级封网状态。
   - 封网期间只允许实施由 VP 级研发负责人与安全负责人双重审批的紧急缺陷修补（Hotfix）。

## 第三章 线上生产发布安全红线（十大铁律）

### 第五条 生产安全十大红线
全体技术人员在任何生产环境操作中，严禁触犯以下“十大安全红线”：
1. **严禁绕过 CI/CD 自动化流水线直接向生产服务器通过 SSH/SCP 传输可执行文件、修改依赖包或手动打热补丁。**
2. **严禁未经 DBA 审核与工单审批，擅自直连生产主从数据库执行 DDL、DML 批量写入、Truncate 或 Drop 表操作。**
3. **严禁在代码仓库、公共配置文件、前端包或公开 Docker 镜像中硬编码包含任何明文密码、私钥证书、云厂商 AccessKey/SecretKey、JWT 签名私钥。**
4. **严禁在发布过程中实施无灰度、无金丝雀（Canary）验证的直接 100% 流量一次性切换。金丝雀流量切分观察期不得少于 15 分钟。**
5. **严禁在未准备好经过实测验证的一键回滚方案（Rollback Script / Canary Rollback）的情况下执行生产变更。**
6. **严禁在生产环境代码中开启 Debug 级别全局日志打印，严禁在生产日志中明文打印用户身份证号、银行卡号、手机号、密码哈希等敏感个人隐私数据。**
7. **严禁私自在生产主机上开启非常规对外监听端口，严禁将生产集群内部内网通信服务（如 Redis、Kafka、Elasticsearch）直接暴露至公网。**
8. **严禁在未经过沙箱隔离与安全团队授权的情况下，向生产系统引入未经合规扫描与漏洞审计的外部第三方 SDK 或开源组件。**
9. **严禁擅自修改生产网关、负载均衡（Nginx/SLB）的核心路由策略与限流熔断阈值。**
10. **严禁发生线上故障后瞒报、谎报、延迟报警超过 15 分钟，或私自删除生产系统审计日志以掩盖事故根因。**

## 第四章 违规问责与等级处置

### 第六条 事故责任追究机制
1. **轻微违纪（未造成生产故障或服务中断）**：
   - 违反发布窗口纪律但未造成业务影响，或代码提交含中低危漏洞者，由部门技术总监进行正式诫勉谈话，并在技术全员例会上通报批评，扣减当季度绩效 0.5 分。
2. **严重违纪（触碰十大红线但被监控拦截）**：
   - 取消当季度绩效评优资格，当年度年终奖绩效系数直接降级为 0.5，且 12 个月内不得晋升提拔。
3. **重大责任事故（触犯红线导致 P1/P0 级线上生产瘫痪或严重数据泄漏）**：
   - 集团认定为严重违反公司规章制度，公司将根据《劳动合同法》第三十九条规定，依法无偿单方解除劳动合同，不予支付任何经济补偿金；若涉及违法犯罪行为，将依法移交司法机关追究刑事责任。
