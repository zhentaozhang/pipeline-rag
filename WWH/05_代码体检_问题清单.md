## A 类 · 疑似 Bug / 正确性问题

### A1 ✅ 向量化 UPSERT 冲突目标无匹配唯一约束（已实测确认 + 已修复）
- **位置**：`app/document/vectorizer.py:112`（`ON CONFLICT (document_id, chunk_no)`） vs `app/infra/pg.py:112`（建表仅 `PRIMARY KEY (id)`）
- **描述**：`pipeline_rag_document_embedding` 表只由 `_ensure_pg_tables()` 启动时 `CREATE TABLE IF NOT EXISTS` 创建；全仓库（alembic 0 个文件）无 `(document_id, chunk_no)` 唯一索引。PostgreSQL 要求 ON CONFLICT 目标必须匹配唯一索引，否则执行期报 42P10。
- **影响**：**实测确认**——新环境下首次向量化写入必然失败（即使表为空），Celery 任务重试 3 次后失败，文档向量化功能不可用；老环境取决于表实际结构。
- **验证记录**：本地启动 pgvector/pgvector:pg16 容器实测——复刻建表后执行 vectorizer 的 UPSERT，报 `SQLSTATE=42P10 | there is no unique or exclusion constraint matching the ON CONFLICT specification`（表空也报错）；修复后唯一索引创建成功、首次插入与重复插入（upsert 更新）均正常。
- **修复**：`app/infra/pg.py::_ensure_pg_tables()` 新增 `CREATE UNIQUE INDEX IF NOT EXISTS uk_embedding_document_chunk ON pipeline_rag_document_embedding (document_id, chunk_no)`（幂等 + suppress 容错，与同函数风格一致）。
- **状态**：✅ 已确认（实测）+ ✅ 已修复

### A2 ✅ embedding 失败写入零向量 + 硬编码维度 + 共享引用
- **位置**：`app/document/vectorizer.py:63`
- **描述**：`child_embeddings.extend([[0.0] * 1536] * len(batch))` —— ① 维度硬编码 1536，未引用 `settings.llm.embedding_dimensions`；② `[[0.0]*1536] * n` 是同一 list 的 n 个**共享引用**；③ 失败时静默写全零向量，进向量表后被检索命中（零向量 cosine 相似度无定义）。
- **影响**：换 embedding 模型（维度≠1536）时必炸；零向量污染检索与评估。
- **验证记录**：Python 实测 `[inner]*2` 中 `a[0] is a[1] == True`、修改连带生效；grep 确认 vectorizer.py 无 `embedding_dimensions` 引用、含硬编码 `1536`。
- **状态**：✅ 已确认

### A4 ✅ 流式超时是"单块空闲超时"而非总时长，超时被记为成功
- **位置**：`app/chat/service_utils.py:80-91`（`wait_for(anext(gen), timeout=600)`）；`app/chat/service_finalizer.py:48-52`（turn_status 判定）
- **描述**：超时作用于**每一个 chunk** 而非整轮——只要流每 <600s 出块即可无限运行。超时后生成器静默 return：**不发送 DONE/ERROR**，`turn_stopped=False、turn_failed=False → turn_status=2（成功）`，半截答案被持久化为完整轮次。
- **影响**：长 Agent 任务（多工具调用）无法被总时长约束；超时截断轮次在历史/评估中被误判为成功；客户端收不到 DONE。
- **验证记录**：直接调用真实 `_async_generator_with_timeout` 实测——① 每块 0.3s×5 块、超时参数 1s：总时长 1.5s 仍全部完成（非总时长语义确认）；② 单块停顿 2s>0.5s：提前终止、无异常、静默。静态确认 service.py 无 TimeoutError 分支、finalize 走 turn_status=2。
- **状态**：✅ 已确认
